1. Definition before use — is every term the document relies on (names of roles, folders, artifacts, protocols, acronyms) defined, in a clause, before its first use in reading order, or pointed at a file that defines it, at or before that first use? List each term used before its definition or never defined, with the line number of its first use.
2. Forward references — does any line depend on something stated only later in the file (a rule, a path, a definition, a section), so that reading top to bottom the line cannot be understood or applied at the point it appears? List each, with the line and the later line it depends on.
3. Explicit premises — for each rule or instruction, is the premise it rests on stated (why it holds, or what fact makes it apply), or is the reader left to supply an unstated reason or condition? List each rule whose premise is missing or only implied, with the line.
4. Implicit knowledge — what does the document assume the reader already knows that it neither states nor points at a file for (history, prior decisions, conventions, the meaning of a jargon word, how a process works)? List each assumption, with the line where it is first needed.
5. Paths and instance strings — (a) is every path in the document written from the project's root with the configured prefix (`audit-root-prefix`), none by default (a layout diagram in a fenced block excepted), and does any path start with a slash, omit that prefix, or point at a location that would differ between projects? (b) does the document carry anything specific to one workspace: a workspace's name, a person's name or handle, a machine path, a repository that only one workspace holds? List each with its line.
